## Conversion commands and verification

Built-in macOS `sips` decoded HEIC to lossless temporary PNGs:

```sh
sips -s format png frontend/public/images/tmk/IMG_0897.heic --out /tmp/tmk-asset-0897.png
sips -s format png frontend/public/images/tmk/IMG_5872.heic --out /tmp/tmk-asset-5872.png
sips -s format png 'frontend/public/images/tmk/IMG_9737 2.heic' --out /tmp/tmk-asset-9737.png
```

The bundled Python/Pillow runtime then used `ImageOps.exif_transpose`, JPEG `quality=95, subsampling=0`, WebP `quality=92, method=6`, proportional `thumbnail((2000, 2000), LANCZOS)`, and `lossless=True` for the three prepared PNG derivatives. No new packages or system tools were installed. Initial sandboxed `sips` writes failed; rerunning the same conversions with permission outside the sandbox succeeded.

Verification: all 16 renamed originals matched their pre-rename SHA-256 hashes. Each generated file decoded successfully with expected dimensions. Lossless prepared-image derivatives matched the original decoded pixels exactly. All source files were kept; no faces, people, logos, or text were retouched, generated, removed, or added. No existing application references to these original filenames were found.

Final load check: all 26 JPEG/PNG/WebP files opened and decoded successfully in Chrome. The three retained HEIC sources were decoded via `sips` and verified unchanged by SHA-256. All 29 target filenames are unique lowercase kebab-case.
